# OperationRecorder 全面修复计划

## 当前状态分析

### 已完成功能

- ✅ 基础框架搭建（Vue 3 + Vite + CRXJS）
- ✅ 录制功能核心逻辑（recorder.js）
- ✅ 脚本存储（Chrome Storage API）
- ✅ Popup 基础界面
- ✅ Options 设置页面
- ✅ MCP 服务器基础实现

### 关键问题

1. **录制后脚本不显示** - 数据保存逻辑有问题
2. **缺少脚本编辑器** - 无法编辑录制的动作
3. **录制悬浮工具栏** - 可能未正确显示
4. **Content Script 注入** - 动态注入机制不稳定

---

## 修复步骤

### 阶段一：修复核心数据流（优先级：P0）

#### 1.1 修复脚本保存逻辑

**问题**：录制后脚本没有出现在列表中

**检查点**：

- [ ] `stopRecording` 是否正确获取录制数据
- [ ] `createNewScript` 是否正确创建脚本
- [ ] `addAction` 是否正确添加动作
- [ ] `saveScript` 是否正确保存到 storage
- [ ] `loadScripts` 是否正确加载并触发响应式更新

**修复方案**：

1. 在 `PopupContent.vue` 添加详细调试日志
2. 检查 `scriptsStore` 的响应式更新逻辑
3. 确保 `scriptList` computed 属性正确计算

#### 1.2 修复 Content Script 注入

**问题**：动态注入机制不稳定，文件名变化导致问题

**修复方案**：

1. 使用 `chrome.scripting.executeScript` 的 `func` 方式直接注入代码
2. 或者通过 background 脚本中转消息
3. 添加更健壮的错误处理和重试机制

---

### 阶段二：实现脚本编辑器（优先级：P0）

#### 2.1 创建 ScriptEditor 组件

**功能需求**：

- 显示脚本的所有动作列表
- 支持编辑动作参数
- 支持删除动作
- 支持添加新动作
- 支持拖拽排序（可选）

**组件结构**：

```
ScriptEditor.vue
├── 头部：脚本名称编辑 + 保存/取消按钮
├── 动作列表：
│   ├── ActionItem（每个动作的编辑行）
│   │   ├── 动作类型图标
│   │   ├── 参数编辑表单（根据类型变化）
│   │   ├── 删除按钮
│   │   └── 拖拽手柄
│   └── 添加动作按钮
└── 底部：统计信息（动作数、预计执行时间）
```

#### 2.2 创建 ActionEditor 组件

**支持编辑的动作类型**：

- `navigate`：URL 输入框
- `click`：选择器输入框
- `input`：选择器 + 值输入框
- `wait`：等待类型 + 时间/选择器
- `scroll`：坐标输入
- `keypress`：按键选择

## 风险与备选方案

### 风险

1. **CRXJS 构建问题** - 可能导致开发模式不稳定
2. **Chrome API 权限** - 某些功能可能需要额外权限

### 备选方案

1. 如果动态注入不稳定，改用 manifest 静态声明 content script
2. 如果拖拽排序复杂，先用简单的上移/下移按钮
